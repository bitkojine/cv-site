### The Problem: Necromancy in Git

If you work on a long-lived feature branch, merge it, and then accidentally keep working on it locally, you are creating a "Zombie Branch". The original branch was dead (merged), but you are "necroing" it by adding new commits on top of old history.

This is bad hygiene. It leads to:

1.  **Confusing History:** New PRs contain old commits that are already in `main`.
2.  **Merge Conflicts:** You are basing work on stale code.
3.  **CI Waste:** Checksum-based caches miss because the base is old.

We wanted to block this at the source: **The `git push` command.**

### Attempt 1: The Naive Check

Our first attempt was simple: "If my current local commit is already in `main`, block the push."

```bash
# Don't do this
if git merge-base --is-ancestor HEAD origin/main; then
  echo "Blocked!"
  exit 1
fi
```

**Why it failed:** This only blocks you if you haven't done any work yet!
As soon as you add a new commit locally ("necro commit"), your `HEAD` moves _ahead_ of `main`. Git sees: "Oh, this branch has 1 new commit. It's not merged. Safe to push!"

The check was effectively useless against actual zombies.

### Attempt 2: The Remote Ancestor Check

We realized we need to check the **Base** of the branch, not the Tip.
Specifically, we need to check if the **Remote Tracking Branch** (`origin/fix-bug`) is already merged into `origin/main`.

```bash
# Better
REMOTE_TIP=$(git rev-parse origin/HEAD)
MAIN_TIP=$(git rev-parse origin/main)

if git merge-base --is-ancestor $REMOTE_TIP $MAIN_TIP; then
  echo "Blocked: Remote branch is already merged!"
  exit 1
fi
```

This worked perfect! If the PR was merged on GitHub, the remote branch pointer is now an ancestor of `main`. Even if I add 10 local commits, the _remote_ pointer is still stuck in the past (merged). The script sees this and blocks me from extending it.

### The Gotcha: The Zombie Loophole

Then we hit the edge case.
What if the developer (or GitHub auto-delete) **deletes the branch on remote** after merging?

When I try to push my local "necro" branch:

1.  Git looks for `origin/fix-bug`.
2.  It's gone (deleted).
3.  Git assumes I am pushing a **Brand New Feature Branch**.
4.  The script sees "New branch detected" and allows the push.

The zombie rises again! We effectively re-created the branch from the dead.

### The Squash Problem: Structural Proof vs. Heuristics

To fix the Zombie Loophole, we tried to detect if the _content_ of the local branch exists in `main`.

If we used **Squash Merging**, this became a nightmare.

- Local: Commits A, B, C.
- Main: Commit S (Squash of A+B+C).

These commits have different SHA hashes. They have different trees (usually). There is **zero cryptographic link** between them in Git.
`git cherry` (which uses patch-IDs) failed because `diff(S) != diff(A)`.

We tried a brittle heuristic: **Grepping commit logs.**
We searched `git log origin/main` for the _Subject Line_ of our local commits.
It worked... mostly. But it failed if:

- The PR title was edited.
- The commit message was generic ("fix bug").
- The repo was huge (grep is slow).

### The Solution: Structural Integrity

We decided that heuristics weren't good enough for a "High Integrity" codebase. We needed **Structural Proof**.

We switched our workflow to require **Merge Commits** (or Rebase Merges).
Why? Because a Merge Commit preserves the original commit hash in its ancestry graph.

With Merge Commits, our "Zombie Detector" is mathematically perfect:

1.  Is `origin/fix-bug` reachable from `origin/main`? **YES.**
2.  Is the _start_ of my local branch reachable from `origin/main`? **YES.**

We now strip away all the grep hacks and rely purely on the Graph.

### The Final Code

Our `.husky/pre-push` hook effectively does this:

```bash
# Get the tip of the remote branch (the "Base" of our push)
if git show-ref --verify --quiet "refs/remotes/origin/$CURRENT_BRANCH"; then
    ORIGIN_TIP=$(git rev-parse "origin/$CURRENT_BRANCH")
    MAIN_TIP=$(git rev-parse "origin/main")

    # If the remote branch is strictly merged into main...
    if git merge-base --is-ancestor "$ORIGIN_TIP" "$MAIN_TIP"; then
        echo "⛔️ BLOCKING PUSH: DEAD BRANCH"
        echo "This branch was fully merged. Stop necroing it."
        exit 1
    fi
fi
```

If the remote branch is missing (the Zombie Loophole), we accept the risk: **We rely on the developer not to manually resurrect deleted branches.** But for the 99% case of "I forgot I merged this", the protection is solid.
